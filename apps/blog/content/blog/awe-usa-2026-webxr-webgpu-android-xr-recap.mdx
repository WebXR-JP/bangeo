AWE USA 2026はXR業界全体を扱う大型イベントです。Android XR、WebAR、Spatial AI、ARグラス、Gaussian Splatting、空間ブラウザ構想など、ブラウザ上の空間体験に関わる話題が複数取り上げられました。

この記事では、AWE USA 2026の公式レポート（Recap）、基調講演（Keynote）、関連セッションをもとに、WebXR・WebGPU・Android XR周辺の要点を整理します。

## 押さえておきたい4つの視点

AWE USA 2026の発表のうち、Webで空間体験を作る開発者に関係が深い論点は次の4つです。

- **Android XR**：今後のXRデバイスにおけるChrome・WebViewの扱いや、WebXR対応状況に影響する可能性がある
- **SnapなどのAR配信基盤**：ブラウザ配信（WebAR・WebXR）とSNS・専用アプリ配信の違いを比較する材料になる
- **OMBI・Sneeze**：空間サービスを発見・合成・実行するブラウザエンジン構想として、WebXRとは別レイヤーで捉える必要がある
- **Spatial AIとGaussian Splatting**：重い空間データを扱うため、WebGPU・WebAssembly・glTF・ストリーミング・LODといったWeb 3D基盤と密接に関わる

AWEにはハードウェア、エンタープライズ導入、制作ツール、標準化など幅広い発表が集まります。WebXR Device API、Android XR、OpenXR、WebGPU、WebARプラットフォーム、空間ブラウザ構想はそれぞれ担当するレイヤーが異なるため、XR業界のトピックとブラウザAPIの更新を切り分けて読むことが重要です。

### OMBIとSneezeの位置づけ

OMBIは**Open Metaverse Browser Initiative**の略称です（PlexやEmby向けのメディアリクエストアプリ「Ombi」とは別物です）。特定企業に所有されない相互運用可能なメタバースブラウザ基盤を目指し、2D Webのように誰でも空間サービスをホストして標準準拠のクライアントから開ける世界を構想しています。

```txt
2D Web:
  Webサイトを誰でもホストできる
  標準準拠ブラウザなら表示できる
  単一企業がWeb全体を所有しない

Spatial Web:
  空間サービスを誰でもホストできる
  標準準拠の空間ブラウザなら体験できる
  単一企業のXRプラットフォームに閉じない
```

**Sneeze**は、このOMBIの中で発表されたメタバースブラウザエンジンです。WebブラウザにおけるBlink、WebKit、Geckoに相当する役割を空間コンピューティング向けに担う位置づけですが、HTML・CSS・DOMをそのまま置き換える構想とは異なります。公式発表では、次のような課題に取り組む基盤として説明されています。

- 空間サービスの発見
- 複数事業者が提供する3Dコンテンツの同一空間への合成
- 各サービスのセキュリティ境界の保護とWASMサンドボックスの活用
- OpenXR、glTF、SPIR-V、WebAssembly、GeoPoseなどの既存標準との接続
- ARグラス、VR、デスクトップ、モバイルの横断

### 既存Webブラウザとの違いとWebXRとのレイヤー分離

OMBI・Sneezeの問題意識は、2Dドキュメント中心に設計された既存Webブラウザだけでは空間コンピューティングの要件をカバーしきれない点にあります。

ARグラスなどの空間環境では、URLを入力してページを開く行為に加えて、ユーザーの現在地や視線方向、周囲の物理空間に応じて近くのサービスを見つける仕組み（近接ベースのサービス発見：proximity-based service discovery）が求められます。

また、駅のような物理空間では、鉄道会社の案内、店舗のクーポン、自治体の防災情報、友人のアバター、ナビゲーションなど、異なる提供元のサービスが1つの空間に同時表示される可能性があります。互いのデータや権限を分離しながら3Dシーンを合成する仕組みとして、Scene Object Modelやマルチオリジンでの3Dシーン合成（multi-origin 3D scene composition）といった考え方が挙げられています。

WebXRとの役割の違いは、レイヤーで分けると明確になります。

```txt
WebXR:
  WebアプリがXRデバイスへ描画するためのブラウザAPI
  セッション、入力、姿勢（ポーズ）、リファレンススペース、WebGL/WebGPU連携などを扱う

OMBI / Sneeze:
  空間サービスをホスト、発見、合成、実行するためのブラウザエンジン構想
  複数オリジンの3Dサービス、空間インフラ、WASMサンドボックス、標準群の接続を扱う
```

将来的にSneezeのようなエンジンが実装の一部としてWebXR、OpenXR、WebGPU、glTF、WebAssemblyを利用する可能性は十分にあります。ただし現時点で「OMBI＝WebXRの後継」と断定するのは飛躍があり、周辺標準と合わせて動向を追う別レイヤーの基盤構想として捉えるのが妥当です。

### WebGPUやGaussian Splattingとの接点

空間Webで扱うコンテンツは、大量の3Dモデル、Gaussian Splattingの空間スキャン、リアルタイムアバター、空間アンカー、AIエージェント、物理空間に重なるUI、複数ユーザーの同期など、2Dページに比べて負荷が高くなりがちです。

そのため、OMBI・Sneezeのような空間ブラウザ構想だけでなく、WebGPU、WebAssembly、glTF、OpenXR、ストリーミング、LOD、セキュリティ境界といった基盤技術の成熟が並行して重要になります。

## ブラウザ3D・Spatial AIの広がり

AWE USA 2026では、WebXR Device APIの仕様更新に直接結びつく発表が中心だったわけではありません。それでも、WebARやブラウザベースの3D共有事例、Gaussian Splattingや3Dスキャン、Spatial AIによる空間理解、ARグラス向け配信といった周辺テーマは、Webで作れる空間体験の幅を左右します。

WebXRの仕様自体が変わらなくても、端末性能、ブラウザのGPU対応、3Dアセット形式、AR配信基盤、Spatial AIの活用法が進めば、開発者の選択肢は大きく広がります。特にGaussian SplattingやSpatial AIは、WebGPU・WebAssemblyで動作するブラウザ上のビューアや、空間データの配信方式と合わせて注目しておきたい分野です。

## まとめ

AWE USA 2026の動向をWeb開発者の視点で振り返ると、今後の注目点は次の3つに集約されます。

- Android XRがChrome、WebView、WebXR、WebGPUとどう接続していくか
- 専用ARプラットフォームの配信導線が、WebARやWebXRの使い分けにどう影響するか
- Spatial AI、Gaussian Splatting、OMBI・Sneezeのような空間ブラウザ構想がWeb 3D体験とどう交わるか

WebXRは空間Web全体を構成する重要な柱の1つです。AWEのような総合イベントの話題は、ブラウザ、GPU、3Dアセット、XRデバイス、空間サービスのつながりを俯瞰する材料として押さえておくと、今後の技術選定に生かしやすくなります。
