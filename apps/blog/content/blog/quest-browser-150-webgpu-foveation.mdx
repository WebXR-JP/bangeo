Metaは2026年8月28日公開の[Quest Browser 150.1リリースノート](https://developers.meta.com/horizon/downloads/package/browser/150.1/)で、WebXRのWebGPU描画におけるfoveation（視野の中心より周辺の描画密度を下げ、GPU負荷を抑える技術）の実験的なサポートを発表しました。WebXRでのWebGPU対応に続き、描画負荷を調整する機能が加わりました。

動作を確かめられるよう、BANGEOでは[WebGPUの比較デモ](/demos/webgpu-foveation-comparison/index.html)を用意しました。fixed foveation（視線追跡を使わない固定方式）の設定を、最小値の0と最大値の1の別々のページで試せます。Blenderで作った魚型の3DモデルにUVテクスチャを貼り、視野の中央と左右に配置しました。VR画面に重なって見える同心円や格子は使わず、淡い単色の背景にしています。設定ごとにVRを開始し、モデルの模様を比べてください。

デモページにはモデルの動きを示す短いアニメーションもあります。3Dモデルのプレビューであり、VRシーンやfoveationの効果を撮影した映像ではありません。ヘッドセットがなくても、モデルの形を確認できます。

![Blenderで制作したBANGEOの魚型3Dモデルがゆっくり向きを変えるプレビュー](/demos/webgpu-foveation-comparison/assets/bangeo-fish-preview.gif)

## 150.1で変わったこと

Quest Browser 150.1のリリースノートには、WebXRのWebGPU描画に対するfoveationの実験的なサポートが記載されています。同じリリースにはMV-HEVC動画再生の有効化と、信頼性・セキュリティ・性能の改善も含まれます。対応する方式やQuest機種ごとの効果、性能向上率は示されていません。[Quest Browser 149.1](https://developers.meta.com/horizon/downloads/package/browser/149.1/)ではWebGPU用Space Warp Layer、[Quest Browser 146.0](https://developers.meta.com/horizon/downloads/package/browser/146.0/)ではWebXRでの実験的なWebGPU対応が案内されていました。

| Browser | 公式リリースノートにあるWebXR / WebGPU関連の更新 |
| --- | --- |
| 146.0（2026年4月21日） | WebXRでの実験的なWebGPU対応 |
| 149.1（2026年7月27日） | WebGPU用Space Warp Layer対応 |
| 150.1（2026年8月28日） | WebXRのWebGPU描画でfoveationを実験的にサポート |

[Metaのfixed foveationの解説](https://developers.meta.com/horizon/documentation/web/webxr-ffr/)によると、GPUのピクセル処理がボトルネックになっている場面で効果が期待できます。一方、コントラストの高い画像や文字では、画質の変化が目立つことがあります。

## デモを始める前のWebGPU設定

このデモはWebXRセッション内でWebGPUを使って描画します。Quest BrowserでWebGPUとWebXRのWebGPU連携を使える状態にしてください。VRを開始できない場合は、Browserで`chrome://flags`を開き、`WebXR/WebGPU Binding`と`WebXR Projection Layers`を検索して、両方を`Enabled`に設定します。変更後は画面の案内に従ってBrowserを再起動し、デモを開き直してください。[Chromiumの設定説明](https://chromium.googlesource.com/chromium/src/+/bf517330f1f8f20a208aae7fa2abd55657dd0e1e/chrome/browser/flag_descriptions.cc)にも、`WebXR/WebGPU Binding`には`WebXR Projection Layers`の有効化が必要と記されています。

![Quest Browserのchrome://flagsでWebGPU関連設定を検索した画面。WebXR/WebGPU BindingはDisabledの状態](/demos/webgpu-foveation-comparison/assets/quest-browser-flags-privacy.webp)

画像は設定を変更する**前**の状態で、`WebXR/WebGPU Binding`は`Disabled`です。撮影時には`Unsafe WebGPU Support`と`WebGPU Developer Features`も有効でしたが、これらがこのデモの必須条件であることは確認できていません。設定名と現在値はご自身の端末で確認してください。

## 比較デモの操作

1. WebGPUとWebXRに対応したQuest Browserで[比較デモ](/demos/webgpu-foveation-comparison/index.html)をHTTPSで開き、「最小設定（0）を開く」か「最大設定（1）を開く」を選びます。
2. 選んだページで「VRを開始」を押します。デモは`immersive-vr`セッションで`webgpu`機能を要求し、`XRGPUBinding`からWebGPU用`XRProjectionLayer`を作ります。
3. 中央と左右に置いた魚型モデルの模様を観察します。設定値は起動したページで固定され、コントローラーの操作では変わりません。
4. VRを終了して比較ページに戻り、もう一方の設定を開きます。なるべく同じ頭の向きで見え方を比べてください。
5. 画面収録やスクリーンショットを残す場合は、0と1の両方を記録し、Questの機種、Quest Browserのバージョン、設定を添えると比較しやすくなります。

![Quest BrowserでBANGEOのWebGPUデモを開いた様子](/demos/webgpu-foveation-comparison/assets/quest-browser-demo-privacy.webp)

Quest Browserでデモを開いた画面です。2026年9月24日の撮影後に操作方法を変更し、現在は最小設定と最大設定を別々のページで開きます。

各ページには、指定値とProjection Layerから読み取った値を表示します。`fixedFoveation`が`null`の場合は、その環境でこの属性を使えないため、VRを開始できない理由を表示します。読み取り値が0または1であっても、それだけでGPUの負荷軽減や画像上の効果まで証明できるわけではありません。Metaのドキュメントでは、実効を調べる方法として`ovrgpuprofiler -t`による確認も紹介しています。

## デモが使うAPIと比較の意味

デモはWebGPUのRender Pipelineで、UV展開した3Dモデルのテクスチャをサンプリングします。中央と左右のモデルは3D空間に配置し、`XRGPUBinding.getViewSubImage()`で得た左右それぞれのProjection Layerのテクスチャへ直接描画します。WebGPU対応の有無を`navigator.gpu`だけで判定せず、WebXR、`XRGPUBinding`、`immersive-vr`の対応を個別に確認します。

設定に使うのは[`XRProjectionLayer.fixedFoveation`](https://www.w3.org/TR/webxrlayers-1/#dom-xrprojectionlayer-fixedfoveation)です。[WebXR Layers API Level 1](https://www.w3.org/TR/webxrlayers-1/)では、0が最小、1が最大で、具体的な描画方式と段階の解釈はブラウザ側に委ねられています。対応しない環境では`null`を返し、値を設定しても効果はありません。各ページはVR開始時にそれぞれの値を設定します。

このデモが扱うのは**fixed foveation**です。視線追跡で注視点を追う方式は扱いません。ページに表示する設定値は、描画負荷の変化を示すものではありません。スクリーンショットだけではヘッドセットで見たときの周辺視野の印象が伝わりにくいため、画質は装着した状態でも確かめてください。

`fixedFoveation = 0`は仕様上の最小値です。ブラウザ側の描画処理が完全に無効になることまでは保証されません。デモの表示にも、仕様上の範囲を表す「最小（0）」「最大（1）」を用いています。

## 開発時に見るポイント

今回の更新によって、WebGPUで描画するWebXRアプリでもfixed foveationを試せます。効果はピクセル処理の負荷やシーンの細かさ、UIの位置、Quest Browserと端末の実装によって変わります。線や文字を多用する画面では、周辺部の読みやすさを確認してください。

実験的なサポートのため、製品への採用を判断するときは対象端末で設定値ごとの画質とGPU負荷を測り、Quest Browserの更新後にも確かめる必要があります。WebGPUを使ったXR描画の実装例として、[Immersive WebのWebGPUサンプル](https://immersive-web.github.io/webxr-samples/webgpu/)も参考になります。
