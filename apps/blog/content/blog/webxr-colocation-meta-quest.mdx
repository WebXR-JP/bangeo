## はじめに

Quest Browser（39以降）では、同じ部屋にいる複数のヘッドセットが自動的に座標系を共有できる実験機能**「Shared Spaces」**が公開されています。

本記事では、この機能を使ったデモの体験方法と技術的な仕組みを解説します。

## デモの体験

まずは実際に動作するデモを試してみてください。

デモURL：[/demos/webxr-colocation/](/demos/webxr-colocation/)

> **必要な機器**：Meta Quest 2台以上（同じ物理空間に配置）

### このデモでできること

| 機能 | 説明 |
| --- | --- |
| 自動マッチング | 同じ部屋にいるユーザーは自動的に同じUUIDを取得するため、サーバー側で簡単にマッチングできます。 |
| 位置同期 | 他のプレイヤーの位置がcm単位の精度で見えます。 |
| 弾丸発射 | トリガーを引くと弾が飛び、相手側からも同じ軌道で見えます。 |

## WebXR Shared Spacesとは

**同じ物理空間にいる複数のQuestヘッドセットが、自動的に共通の座標系を共有する機能**です。

### 従来の課題

複数人でARコンテンツを共有するには、従来は以下のような手間がかかっていました。

- QRコードやARマーカーを配置する
- 全員が同じ場所に立って原点を合わせる
- GPSやコンパスで位置を合わせる（精度が低い）

### Shared Spacesが解決すること

ブラウザが以下の処理を自動で行います。

1. **空間スキャン（spatial mapping / scene capture）**：部屋の形状をスキャンします。
2. **共通座標系の確立**：全員が同じ原点`(0, 0, 0)`を共有します。
3. **一意のUUID発行**：同じ空間にいるヘッドセットだけが同じUUIDを取得します。

## 同じUUIDが生成される仕組み

UUIDは**Metaのサーバーから配布されるのではなく**、各デバイスが独立して同じ値を算出します。

### 処理の流れ

ベースになっているのは、Meta Questの**Spatial Anchors**技術です。

| ステップ | 処理内容 |
| --- | --- |
| 1. 空間スキャン | Questのカメラ・センサーが部屋の壁、床、家具などの**特徴点（feature points）**を検出します。 |
| 2. 空間ハッシュ生成 | 特徴点データから**一意のハッシュ値（UUID）**を算出します。 |
| 3. 座標系の確立 | 空間の特徴から**共通の原点`(0, 0, 0)`**を決定します。 |
| 4. UUIDの一致 | 同じ部屋にいる全デバイスが同じ特徴を観測するため、**同じUUIDが生成されます**。 |

### 押さえておきたい特徴

- 同じ部屋であれば同じUUID、別の部屋であれば異なるUUIDが生成されます。
- 一度スキャンした部屋は再現性があり、後日アクセスしても同じUUIDになる可能性が高いです。
- 位置合わせはサブセンチメートル精度（1cm未満の誤差）で一致します。

![Shared Spaces UUID同期の仕組み](/images/tech-articles/shared-spaces-uuid-sync.png)

### 補足：サイト分離

セキュリティ上の理由から、**URLごとに別のUUID**が生成されます。同じ部屋にいても、以下のように別々のUUIDが割り当てられます。

- `example.com/game-a`と`example.com/game-b` → 別のUUID
- `example.com/game-a`と`another.com/game-a` → 別のUUID

これにより、異なるサイト間でユーザーが意図せずマッチングされることを防いでいます。

## セットアップ手順

### 手順1：WebXR実験機能の有効化

1. Quest Browserで`chrome://flags`を開きます。
2. 「WebXR experiments」を検索します。
3. フラグを**Enabled**に変更します。
4. ブラウザを再起動します。

### 手順2：デモへのアクセス

1. 2台のQuestを**同じ部屋**に用意します。
2. 両方の端末で[/demos/webxr-colocation/](/demos/webxr-colocation/)にアクセスします。
3. 「START AR」ボタンをタップします。
4. 数秒待つと**Space UUID**が表示されます。
5. 両方のQuestで同じUUIDが表示されれば準備完了です。

### 手順3：マルチユーザー体験の操作

- コントローラーのトリガーを引くと弾丸が発射されます。
- お互いの位置と弾丸の動きがリアルタイムで同期されます。

## APIの使い方と技術的な仕組み

```javascript
// ARセッション開始時に 'shared' を要求
navigator.xr.requestSession('immersive-ar', {
  requiredFeatures: ['local-floor'],
  optionalFeatures: ['shared', 'unbounded']
}).then(session => {
  // 共有空間を取得
  session.requestReferenceSpace('shared').then(space => {
    console.log('Shared space UUID:', space.uuid);
    // このUUIDが同じ部屋にいる全員で一致する！
  });
});
```

### resetイベントの重要性

共有空間のUUIDは、セッション開始直後の段階では**一時的な値**です。正しいUUIDは数秒後に`reset`イベントで確定します。

```javascript
space.addEventListener('reset', () => {
  // ここで取得したUUIDが本物
  const realUUID = space.uuid;
  registerWithServer(realUUID);
});
```

## 弾丸の発射と当たり判定の仕組み

マルチプレイヤーARでの弾丸発射と当たり判定は、以下の流れで処理しています。

### 1. 弾丸の発射とアニメーション

コントローラーのトリガーを引くと、弾丸オブジェクトを生成します。

```javascript
// トリガー検出
controller.addEventListener('selectstart', () => {
  // 弾丸を生成
  const bullet = new THREE.Mesh(bulletGeometry, bulletMaterial);
  bullet.position.copy(controller.position);

  // 弾丸の進行方向を計算
  const direction = new THREE.Vector3(0, 0, -1);
  direction.applyQuaternion(controller.quaternion);
  bullet.userData.velocity = direction;

  bullets.add(bullet);
});
```

### 2. 位置の同期（PeerJS）

自分の弾丸の座標は、PeerJSを通じて他のプレイヤーへリアルタイムに送信します。

```javascript
// 全弾丸のワールド座標を収集
const bulletPositions = [];
bullets.children.forEach(bullet => {
  const pos = new THREE.Vector3();
  bullet.getWorldPosition(pos);
  bulletPositions.push({ x: pos.x, y: pos.y, z: pos.z });
});

// ピアに送信
connection.send({
  position: myPosition,
  bullets: bulletPositions
});
```

### 3. 当たり判定（距離計算）

各プレイヤーのローカル環境で、受信した弾丸と自分の位置との距離を計算し、しきい値未満であればヒットと判定します。なお、この処理はWebXR Hit Test Moduleによる現実空間との交差判定ではなく、3D空間上のシンプルな距離計算です。

```javascript
function detectHits() {
  const HIT_THRESHOLD = 0.3; // 30cm以内でヒット

  peers.forEach((peer, peerId) => {
    peer.bulletGroup.children.forEach(bullet => {
      // 弾丸と自分の距離を計算
      const distance = bullet.position.distanceTo(myPosition);

      if (distance < HIT_THRESHOLD) {
        // ヒット！
        reportHit(peerId);
      }
    });
  });
}
```

## 制約と注意点

- Quest専用の実験機能であるため、他社デバイス（Apple Vision Proなど）では動作しません。
- Quest Browser 39以降が必要であり、古いバージョンでは動作しません。

## 用語メモ

- **Spatial Anchors**：Questの空間アンカー機能です。WebXRではAnchors Moduleに対応します。
- **空間スキャン（scene capture）**：Questで部屋の形状を取得する機能で、空間マッピング（spatial mapping）の一部です。
- **特徴点（feature points）**：空間の位置合わせに使う目印となる点群データです。
