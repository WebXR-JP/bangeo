PlayCanvas Engine v2.19.7が2026年6月12日に公開されました。大きな新機能を追加するリリースではなく、**WebGPU/WebXRデモを実機で動かす際の安定性を高める修正アップデート**です（[PlayCanvas公式リリースノート](https://github.com/playcanvas/engine/releases)）。

WebXRではコードの正しさだけでなく、どのブラウザ・端末・GPU・入力デバイスで動かすかが再現性に直結します。PlayCanvasでWebXRデモやWebGPUデモ、HTML-in-Canvas UIデモを公開する開発者に向けて、今回の変更点と実機確認のポイントを整理します。

## v2.19.7の主な変更点

リリースノートには、WebXR/WebGPU開発に関わる以下の修正が含まれています。

- **特定GPUでのWebGPU一時無効化**：Imagination PowerVR GPU（Pixel 10など）を対象に、WebGPU経路を一時的に無効化しました。
- **`XrNavigation`のNaN不具合修正**：サムスティック軸を持たないゲームパッドを接続した際、XRナビゲーション用のリグ座標がNaNになって壊れる問題を修正しました。
- **シーン深度デコードの選択修正**：シーン深度（scene depth）のデコード方式の選択処理を見直しました。
- **被写界深度（DOF）エフェクトの調整**：解像度に依存しない挙動へ修正しました。

## v2.19系全体の流れと位置づけ

PlayCanvas Engineは、WebGL2とWebGPUの上に構築され、WebXRによる没入型AR/VR体験をサポートするオープンソースの3Dエンジンです（[GitHubリポジトリ](https://github.com/playcanvas/engine/tree/v2.19.7)）。実際のWebXRデモでは、端末・GPU/ドライバ・OS/ブラウザ・WebXR/WebGPU/Permissions Policy・PlayCanvas Engine・アプリ側の実装という複数の層が重なります。

v2.19.7単体は小さな修正リリースに見えますが、v2.19系全体を見るとWebGPUとWebXRの連携が大きく進んでいます。v2.19.0では`XrBridge`をはじめ、WebGPUでの没入型XR表示、デバイスロスト処理、ARカメラ映像の取得、XR深度ブリッジ、マルチビューのフレームパスなどが追加されました。さらにv2.19.2では、WebGPUの`copyElementImageToTexture`経由でHTML-in-Canvasテクスチャを扱う対応と、新しいテクスチャアップロードAPIへの更新が入っています。

v2.19.7は、こうしたv2.19系のWebGPU・WebXR・HTML UIテクスチャ機能を実機で壊れにくくするための仕上げの更新と捉えられます。

## WebGPU対応確認の注意点

WebGPUの対応判定では、`navigator.gpu`の有無だけで判断しがちです。しかし、v2.19.7でImagination PowerVR GPU向けにWebGPUが一時無効化されたことから分かるように、WebGPU対応ブラウザであっても、端末・GPU・ドライバ・ブラウザの組み合わせによってはWebGPU経路を使わない判断が必要になります。

アプリ側ではWebGPU前提で初期化せず、利用できない場合のWebGLフォールバックを用意しておくのが現実的です。

```js
async function detectWebGPU() {
  if (!("gpu" in navigator)) {
    return false;
  }

  try {
    const adapter = await navigator.gpu.requestAdapter();
    return !!adapter;
  } catch (error) {
    console.warn("WebGPU detection failed:", error);
    return false;
  }
}

const canUseWebGPU = await detectWebGPU();

console.log("WebGPU available:", canUseWebGPU);
```

PlayCanvas側が内部で特定GPUを回避するケースもあるため、「ブラウザにWebGPU APIが存在する」ことと「対象デモがWebGPU経路で安定動作する」ことは分けて確認してください。

## 入力デバイスの差異を前提にした実装

XR環境では、コントローラー、ハンドトラッキング、ゲームパッド、OS側の仮想入力など、利用される入力デバイスが環境ごとに異なります。入力に左右スティックが必ず備わっている前提の実装は、実機で破綻しやすくなります。

v2.19.7の`XrNavigation`修正はエンジン内部の対応ですが、アプリ側でもサムスティック軸が存在しないケースを想定したガード処理を入れておくと安全です。

```js
function readThumbstick(inputSource) {
  const gamepad = inputSource.gamepad;

  if (!gamepad || !Array.isArray(gamepad.axes)) {
    return { x: 0, y: 0, available: false };
  }

  const x = Number.isFinite(gamepad.axes[2]) ? gamepad.axes[2] : 0;
  const y = Number.isFinite(gamepad.axes[3]) ? gamepad.axes[3] : 0;

  return { x, y, available: true };
}
```

PlayCanvasの移動システムやXRメニューを組み込む際は、コントローラーあり、ハンドトラッキング、入力なし、モバイルARといった複数条件で動作を確認しておくと問題を切り分けやすくなります。

## シーン深度を使うデモの実機検証

シーン深度は、仮想オブジェクトが現実の机や壁の後ろに隠れるオクルージョン（遮蔽表現）など、MRデモの品質を左右する要素です。[Meta Quest Browser 146.0](https://developers.meta.com/horizon/downloads/package/browser/146.0?view=full_width)でも、WebXRでの実験的なWebGPU対応に加えてブラウザ内のWebXR Depth Projection（WebXR Depth Sensing Moduleに基づく深度投影）サポートが追加されています。

深度系の機能は端末、ブラウザ、セッションモード、権限、AR/MR環境によって挙動が変わりやすい領域です。シーン深度を使うデモでは、単に起動したかどうかだけでなく、オクルージョンが意図どおりに出るか、左右の目で破綻しないか、WebGPUとWebGLで差が出ないかまで実機で確認してください。

## まとめ

PlayCanvas Engine v2.19.7は、派手な新機能こそないものの、WebGPU/WebXRデモの公開品質に直結する安定化アップデートです。実験的なWebGPUやHTML-in-Canvasテクスチャを扱うデモでは、APIの有無だけでなく、特定GPUでのフォールバック、入力デバイスの差異、シーン深度の描画結果まで含めて実機検証を行うことが重要になります。
