Metaは、2026年11月13日付の[Browser 156.0リリースノート](https://developers.meta.com/vr/downloads/package/browser/156.0/)で、**WebXRにおけるWebGPUのサポート**を新機能として記載しました。あわせて、Chromium 156への更新と、OS全体を更新せずにWebViewを更新する実験機能を案内しています。

WebGPU in WebXR自体が156.0で初めて登場したわけではありません。146.0では実験的な対応として案内されており、今回はその経緯と156.0の記述を分けて見ていきます。

![VRヘッドセットを着けたキャラクターとGPUを持つキャラクターが、ブラウザ内の3Dシーンを囲む概念イラスト](/assets/news/quest-browser-156-webgpu-webxr.webp)

*WebGPUとWebXRの連携を表すイメージ。実機画面ではありません。*

## 156.0の主な更新

| 項目 | 公式リリースノートの内容 |
| --- | --- |
| WebGPU in WebXR | WebXRでのWebGPUサポートを新機能として記載 |
| WebView | OS全体の更新を伴わない更新を実験的に提供。一部ユーザーのみ対象 |
| Chromium | Milestone 156へ更新し、標準対応とセキュリティを改善 |
| その他 | パフォーマンス、信頼性、セキュリティの改善 |

WebViewの更新は、WebXRでWebGPUを使うための条件として記載されたものではありません。別の実験機能であり、全ユーザーへの提供も示されていません。

## 146.0から続くWebGPU in WebXRの対応

WebXRはVR/ARセッションや姿勢・入力を扱うAPI、WebGPUはGPUによる描画や計算処理を扱うAPIです。両者を組み合わせることで、WebGPUの描画結果をXR体験に利用できます。

Meta Browserでは、これまでも関連機能が段階的に追加されてきました。

![146.0の実験対応から、Space Warp Layer、foveation、Composition Layersを経て、156.0のサポート記載に至る時系列](/assets/news/quest-browser-156-webgpu-webxr-timeline.webp)

*各版の公式リリースノートを基に作成。日付は公式ページの表記です。*

| バージョン・公式ページの日付 | WebXR/WebGPU関連の更新 |
| --- | --- |
| [146.0](https://developers.meta.com/vr/downloads/package/browser/146.0/)・2026年4月21日 | WebXRでのWebGPUを実験的にサポート |
| [149.1](https://developers.meta.com/vr/downloads/package/browser/149.1/)・2026年7月27日 | WebGPU用のSpace Warp Layerに対応 |
| [150.1](https://developers.meta.com/vr/downloads/package/browser/150.1/)・2026年8月28日 | WebGPU in WebXRのfoveationを実験的にサポート |
| [152.1](https://developers.meta.com/vr/downloads/package/browser/152.1/)・2026年10月2日 | WebGPUのComposition Layersを実験的に追加 |
| [156.0](https://developers.meta.com/vr/downloads/package/browser/156.0/)・2026年11月13日 | WebGPU in WebXRのサポートを記載 |

146.0の該当項目には実験機能であることが明記されていますが、156.0のWebGPU項目には同じ注記がありません。ただし、**この短い記述だけでは、すべての端末で実験フラグが不要になったことや、関連機能が一律に通常提供されたことまでは判断できません。**

特に、152.1で追加されたComposition Layersには実験フラグの案内がありました。156.0の一般的なWebGPU対応の記述を、そのまま個別のLayer機能やfoveationの提供条件へ当てはめないようにしましょう。

## 既存のWebXRコンテンツとWebGPU移行の条件

ブラウザを更新しても、WebGLで作られたコンテンツが自動的にWebGPU描画へ置き換わるわけではありません。コンテンツ側のレンダラーやエンジンが、WebGPUとWebXRの組み合わせに対応している必要があります。

導入を検討する際は、ブラウザと端末の環境、エンジンの対応範囲、必要な機能、性能と画質の4点を分けて確認すると原因を切り分けやすくなります。

- Meta Browserの版数、Horizon OS、機種、実験フラグの状態を記録しておきます。
- 通常のWebGPU描画だけでなく、使用する版でXRセッション中のWebGPU描画に対応しているか確認します。
- VR/ARのセッション開始、左右の描画、入力、使用するLayersなどを個別に確認します。
- WebGL版との比較は同じシーンと端末で行い、WebGPUに変更するだけで高速化すると決めつけないようにします。

foveationの仕組みについては、[Quest Browser 150.1の解説と比較デモ](/tech-articles/quest-browser-150-webgpu-foveation)も参考になります。過去の記事に示したバージョンの条件と、156.0での挙動は区別して確認してください。

## 公式発表と実機確認の切り分け

156.0は、WebGPUを利用するWebXRコンテンツを検討するうえで重要な更新です。一方、ブラウザの対応表記、個別機能の利用条件、標準仕様の策定状況、実際のコンテンツの動作は別々の事項です。

本記事は2026年11月18日に公式リリースノートを確認して作成しました。BANGEOでは今回、156.0の実機動作やフラグなしでの利用、機種別の対応状況は検証していません。
