A-Frame 1.8.0が公開されました。同梱のthree.jsがr184へ更新され、`gltf-model`、`cursor`、`hand-controls`、WebXR Layersなど、WebXRコンテンツの実運用に関わる修正がまとまっています。

[A-Frame公式ブログ](https://aframe.io/blog/aframe-v1.8.0/)では「20件を超える不具合修正と15件の改善」と紹介されています。大きな新機能の追加というより、モデル読み込み、入力、レイヤー、周辺機器の挙動を整えた安定化リリースです。

マークアップ中心の小さなシーンであっても、入力コンポーネントやマテリアル・影の設定を使っていると影響を受ける場合があります。ライブラリのURLだけを差し替えて公開するのではなく、以下の5項目を中心に実機で確認しておくと安全です。

## 1. three.js r184への更新

A-Frame 1.8.0では、同梱のthree.jsがr184へ更新されました。

A-Frameの標準コンポーネントだけを使う場合、three.js側の変更を直接意識する場面は多くありません。一方、独自コンポーネントから`object3D`、マテリアル、テクスチャ、レンダラーへアクセスしているプロジェクトでは、three.js側の廃止APIや挙動変更が影響します。

今回の更新では、three.js r183以降で非推奨になった`Clock`を`Timer`へ置き換え、同じく非推奨になった`PCFSoftShadowMap`に合わせて影の設定を整理しています。

既存シーンで次の指定を使っている場合は書き換えが必要です。

```html
<!-- 変更前 -->
<a-scene shadow="type: pcfsoft">

<!-- A-Frame 1.8.0以降 -->
<a-scene shadow="type: pcf">
```

three.js側では現在の`PCFShadowMap`もソフトシャドウとして動作するため、A-Frameのリリースノートでは`pcfsoft`から`pcf`への移行が案内されています。

独自コンポーネント内で`THREE.Clock`やレンダラーの実装詳細へ触れている場合は、A-Frame本体だけでなく[three.js r183・r184の移行ガイド](https://github.com/mrdoob/three.js/wiki/Migration-Guide)も確認しておくと安心です。

## 2. モデルと画像の読み込み安定化

WebXRコンテンツでは、起動時に大きなGLBを読み込んだり、ユーザーの選択に応じてモデルを入れ替えたりします。A-Frame 1.8.0では、この読み込み経路に複数の修正が入りました。

主な変更は次のとおりです。

- 読み込み中に`gltf-model`のURLを変更した際の競合を修正
- 読み込みに失敗した画像を誤ってキャッシュしないよう修正
- 画像が残っているのにローディング画面が早く閉じる問題を修正
- キューブテクスチャがライトプローブへ反映されない問題を修正
- ファイル形式ごとにキャッシュキーを分離

商品バリエーションやアバターを短時間に切り替えるUIでは、古いリクエストの完了が新しいモデル表示へ割り込まないかを確認したいところです。

```javascript
const model = document.querySelector("#preview-model");

model.setAttribute("gltf-model", "/models/variant-a.glb");
model.setAttribute("gltf-model", "/models/variant-b.glb");
```

1.8.0へ更新したら、通信を低速にした状態でも最後に指定したモデルが表示されるか、読み込み失敗後の再試行で画像やモデルが復帰するかを試してください。

## 3. Questコントローラーと`hand-controls`の修正

WebXR開発者にとって、今回もっとも実機確認の価値が高いのは入力まわりです。

A-Frame 1.8.0では、Meta Questコントローラーで`hand-controls`の向きがずれる問題が修正されました。加えて、次のような修正も含まれています。

- トラッキング対象コントローラーの切断・再接続後の挙動を修正
- `cursor`の`click`イベントが別のコントローラーで発火する問題を修正
- `tracked-controls`でコントローラーをプレフィックスではなくIDで識別
- ハンドとコントローラーを切り替えた際にモデルが表示されない問題を修正
- Windows Motion Controllerの軸名を修正

左右の手を同時に使うシーン、コントローラーとハンドトラッキングを切り替えるシーン、片方のコントローラーをスリープから復帰させるシーンでは、既存機能が問題なく動くか確認をおすすめします。

見た目だけでなく、`raycaster`、`click`、ボタン、軸のイベントが意図した側から届いているかもログで確認すると、原因を切り分けやすくなります。

## 4. WebXR Layers非対応環境へのフォールバック改善

A-Frame 1.8.0では、クアッドレイヤーを任意機能（オプショナル機能）として扱う変更が入りました。公式リリースノートでは、Apple Vision ProのようにWebXR Layersをサポートしないデバイスでも動作させるための修正として説明されています。

このほか、`layer`コンポーネントでは次の更新が行われています。

- `XRWebGLBinding`の存在判定を修正
- クアッドレイヤーのジオメトリサイズを修正
- 強制更新用の`needsRedraw`を再導入
- 不要な6枚のキャンバス初期化を削減
- 平面動画の描画に`XRMediaBinding.createQuadLayer()`を利用

重要なのは、「Layersが使えない環境ではXR全体が使えない」と判定しないことです。レイヤーを使える環境では高品質なパネルや動画表示へ切り替え、使えない環境では通常の3Dジオメトリへフォールバックする設計が求められます。

更新後は、Layers対応端末だけでなく、Layersを利用できないブラウザやデバイスでもXRセッションを開始できるか確認してください。

## 5. `material`の`npot`廃止とフィルター指定への移行

`material`コンポーネントでは、WebGL 1時代から残っていた`npot`プロパティが削除され、`minFilter`と`magFilter`が公開されました。

これまでテクスチャの`minFilter`を`linear`にする目的で`npot: true`を使っていた場合は、次のように置き換えます。

```html
<!-- 変更前 -->
<a-plane material="src: #panel; npot: true"></a-plane>

<!-- A-Frame 1.8.0以降 -->
<a-plane material="src: #panel; minFilter: linear"></a-plane>
```

UIパネル、動画、動的キャンバス、2の累乗ではないサイズの画像を使っているシーンは、更新前後でぼやけ方、ちらつき、ミップマップの生成、遠距離での見え方を比較してください。

また、`material`コンポーネントには`premultipliedAlpha`も公開されました。半透明のUIやエフェクトで輪郭に黒や白の縁が出る場合は、テクスチャの生成方法と合わせて検証できます。

## 1.7系からの更新チェックリスト

公開前に、次の順番で確認すると手戻りを減らせます。

1. A-Frameのバージョンだけを1.8.0へ変更し、コンソールの警告とエラーを確認する
2. `npot`と`pcfsoft`を検索し、新しい設定へ置き換える
3. デスクトップの通常表示でモデル、画像、影、カーソルを確認する
4. Quest実機で左右入力、ハンド切り替え、再接続を確認する
5. Layers対応・非対応の両経路でXRセッションを開始する
6. 独自コンポーネントが利用するthree.js APIを確認する
7. 低速回線でモデルの差し替えと読み込み失敗後の再試行を確認する

WebXRコンテンツでは、ブラウザの開発者ツールだけで見つからない不具合もあります。入力の向き、左右の取り違え、レイヤーのフォールバックは、最終的にヘッドセット実機で確認してください。

## まとめ

A-Frame 1.8.0は、派手な新機能よりもWebXRコンテンツの安定運用に効く修正が中心です。特にQuest向けの入力を使うコンテンツや、クアッドレイヤーを利用するUI・動画体験では更新する価値があります。

一方で、three.js r184への更新や`npot`・`pcfsoft`の廃止も含まれるため、バージョン番号だけを差し替えず、入力、モデル、マテリアル、Layersの順に確認したうえで移行を進めるのがおすすめです。
