# BANGEO エージェント指示の監査

監査日: 2026-09-12。対象: main `8082ab2` のリポジトリ内指示。個人のグローバル設定、管理ポリシー、モデル選択、接続先の承認設定は変更していない。

## 根拠と方針

Eric Provencherの [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) を確認した。短く用途が明確なスキル、必要な詳細だけを読む構成、作業規模に合った共通指示、承認境界と完了条件の明確化をBANGEOに適用した。以下はこのリポジトリに対する監査判断であり、モデル性能を測定した結果ではない。

## 監査結果と変更

| 優先度 | 確認した問題 | 対応 |

| 中 | 3スキルのdescriptionが長く、IWSDKが一般的な新規デモ依頼も拾う | 対象ワークフローを短く定義し、WebARと実WebXR APIを区別 |

## 判断境界の具体例

| 依頼 | 期待する進め方 |
| --- | --- |
| 記事の誤字だけ直す | 対象だけ直して差分を確認。デモ要件ヒアリングや画像再生成をしない |
| QuestでHit Testデモを実装 | 実WebXR APIで実装・配置・検証。ARという語だけで8th Wallに変えない |
| デモの企画だけ考える | 企画に留め、コードを書き始めない |
| 実装してPRを出す | 実装・検証・修正・push・PR作成まで。main反映は別の操作として扱う |
| 実機がない | 静的検証や使えるエミュレーターで進め、未確認の挙動を報告 |
| 新たに本番公開する必要がある | 未承認なら差分と影響を用意して公開操作だけ確認 |
| すでに公開まで依頼済み | 同じ承認を取り直さず、環境の権限内で進める |

## 配置と運用

Codexの `.agents/skills/` は既存 `.claude/skills/` への相対symlinkで、実体を複製しない。[公式のスキル説明](https://learn.chatgpt.com/docs/build-skills)にリポジトリ検索場所とsymlinkサポートの記載がある。symlinkを通常ファイルに変換するチェックアウトでは、リンクを有効にするかAGENTS.md記載の実体を直接参照する。

Claude専用builderの `model: sonnet` はClaude設定として残した。Codexのモデル指定にはならない。この変更はGPT-6 Astraに適した指示の整理であり、アプリのモデル選択やグローバル設定を変更するものではない。

今後の依頼には「成果・制約・完了条件」を書けばよい。例:「対象の不具合を修正し、関連する検証で失敗した箇所も直してPRまで完成させて。実機でしか確認できない点は報告して」。毎回長い固定手順を追加する必要はない。

## 検証の範囲

3スキルのfrontmatter検証、Codex側リンクの解決、文書リンク・配置先の実在、差分の空白エラーを確認する。エージェントの実行比較やAstraの性能評価は行っていない。アプリコードを変更していないためアプリのビルド・実機テストは対象外。
